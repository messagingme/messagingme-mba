# Messaging Me setup

Speak the user's language. The tools below belong to the `messagingme` MCP server of this plugin (in Claude Code their
full names start with `mcp__plugin_messagingme_messagingme__`). Explain each step in one or two plain sentences before
doing it; never paste raw tool output at the user. The user does not see tool results: a link or a verification
code exists for them only once you write it, in full, as plain text on its own line (never in a code block, which a
terminal cuts at the edge of the screen).

## The welcome

On a first contact (the `messagingme` tools are not available yet, or `get_setup_state` shows that nothing is done),
start with this welcome, in the user's language, with these figures and no others: never a plan figure from memory or
from another page. If the `messagingme` tools are already available, the server is authorized: leave out step 1. If
the welcome was already given in this conversation (by `/messagingme:demarrer`), do not give it again.

<!-- accueil:debut, generated by npm run plugin:generer from scripts/plugin/generer.ts and src/offres/offres.ts: do not edit by hand -->
**Messaging Me** brings WhatsApp to your app, from here: your WhatsApp number, an AI agent that answers your customers,
and a chat bubble for your site.

- **Free**: 100 contacts including those who write to you, 1,000 templates sent per month, 1 user, driven entirely from here.
- **Pro, €49 excl. VAT per month** (14-day free trial): the console, provided number included, unlimited sends, 1,000 contacts, including those who write to you, 3 users.

**Step 1, required: connect Claude Code (or Codex) to Messaging Me.** Claude acts in your own workspace, so it needs
your agreement, once.

- In Claude Code: type `/mcp`, select `plugin:messagingme:messagingme`, then Authenticate.
- In Codex: run `codex mcp login messagingme`.

A page opens in your browser. Continue with Google: with no account yet, your workspace is created right then, with no
form. Or create your workspace with your email address (we email you a link, where you name your workspace and choose
a password), or sign in with your password if you already have one. Then click Authorize.
Your email address identifies you and receives the service emails (your number, your credit, your plan limits);
with Pro, it also signs you in to the console.

**Then**: your WhatsApp number, an AI agent built from your website, the chat bubble on your site, and a test from your
phone.

## Before anything

- If the `messagingme` tools are not available, the server is not authorized: it is step 1 of the welcome. In Claude
  Code, `/mcp`, select `plugin:messagingme:messagingme`, then Authenticate; in Codex, `codex mcp login messagingme`.
  What the browser page offers is said in step 1 of the welcome: say it from there, never from memory.
- If the user had added the same server by hand before (same address, any name), Claude Code keeps theirs and sets the
  plugin's aside: its tools carry that server's name. If that server uses an API key, the setup tools
  (`start_whatsapp_connection`, `create_agent` and the others that act for a person) are missing from it: when
  `get_setup_state` answers but the tools of `etape_suivante` are not available, ask the user to remove that server
  (`claude mcp remove` followed by its name), then `/mcp`, `plugin:messagingme:messagingme`, Authenticate. Otherwise
  use it as it is.
- **Always start with `get_setup_state`.** It returns what is already done and `etape_suivante`, with the tools for it
  (`outils_suggeres`). Skip what is done. Call it again after each step, and whenever the session resumes.
- Read its `avertissements`: `credit_epuise` (the AI agent cannot answer until the credit is topped up),
  `plafond_ia_atteint` (an Enterprise workspace, whose AI credit is unlimited (`credit_illimite`), reached its monthly
  safety cap: its AI stops until Messaging Me raises it; there is nothing to buy, never offer `buy_credit`),
  `numero_a_activer` (Meta has not finished activating the number), `carte_meta_a_regler` (Meta blocks the WhatsApp
  account for its payment method, so templates do not go out: give the user the numbered steps of
  `etapes_carte_meta`; it usually clears within 20 minutes of adding the card), `repondeur_gele_par_l_offre` (the responder the
  user chose, such as Meta's agent, is frozen by the current plan: tell them, never replace it), `lecture_manquee:<part>`
  (that part could not be read: say so, do not guess). On a workspace linked by QR code (`numero.filiere`
  `application`): `numero_coupe` (WhatsApp cut the number, or the device was removed from the phone: nothing goes
  through) and `numero_en_sommeil` (no message for 30 days, the connection sleeps); the way forward for both is in
  `connecter_numero` below, never a new QR code link.
- A responder already chosen (`repondeur.mode_choisi` is `mba`, `scenario` or `application`) skips the AI agent steps:
  build an AI agent only if the user asks for one.

## connecter_numero: the WhatsApp number

The same questions as the "Get started" page of the website, in the same order: the plan, who pays Meta, the Meta
Business account, the WhatsApp Business app, then, without the app, the number.
**Ask every question of this tree, one at a time.** Skip one only when its answer is stated, in the user's own words
(the request copied from the website names the plan and some answers: skip only those it states) or by `get_setup_state`; never skip one by
assuming its answer. A business that has a phone line may not want to use it, or may have none to spare: "Do you
already have a number you could use?" is asked, never guessed. When `numero.fourni` is
already set and the number is not connected, a number we provide was paid for: resume without asking the questions
again, with `start_whatsapp_connection` in the mode `numero.reprise` gives, never one you guess. `coexistence`: the
number is already in their WhatsApp Business app (its account was created with its verification code); only one step
remains, keeping the app, and you never give the account creation steps again. `fourni_application`: it goes in the
app, whose account is not created yet (a way no longer offered, only resumed when `numero.reprise` gives it). `fourni`:
Meta's window. When `numero.reprise` is null, ask one thing only, about their phone: "Is the number (`numero.fourni`) in the
WhatsApp Business app on your phone?" Yes: `coexistence`. No: question 3 below decides. When a tool refuses a mode and
names another one, use the one it names.

At this step and at `activer_numero`, `get_setup_state` gives the help pages (`aide`), each in French (`fr`) and
English (`en`, for any other language). `aide.guide` asks these same questions as a web page: give it to a user who
hesitates or would rather read them on their own. `aide.depannage` is for a connection that blocks (no code, Meta's
window refuses the number or does not open): give it then. `aide.numero_fourni` shows the way of a number we provide,
through Meta's window, in a 3-minute video and its steps: give it with the link of mode `fourni`, unless the credit line pays (its window is not the one in the video). Never write a help
page address from memory, only these.

Almost nobody knows what a Meta Business account or the WhatsApp Business app is, nor why it matters here: be
didactic. Before the first question, explain these four words in plain sentences, briefly, in the user's language:

- **Meta Business account**: the business's account at Meta (a "business portfolio", formerly Business Manager), on
  business.facebook.com. It is free; someone who advertises on Facebook or Instagram probably has one. Otherwise there
  is nothing to prepare: with their Facebook profile, Meta's window has them create it along the way (the business
  name, an email, the country, the website), then offers to add a payment method.
- **WhatsApp Business app**: the free app for businesses, on a phone, distinct from WhatsApp.
- **API number**: a number connected through Meta to the official WhatsApp API, driven by Messaging Me. It sends the
  messages (confirmations, reminders, campaigns, Shopify messages), and Meta bills them, the templates and, since
  October 2026, the replies beyond a monthly allowance, on a payment method added at Meta.
- **Keeping the WhatsApp Business app**: the number of their WhatsApp Business app also becomes an API number, without
  leaving the app: they keep replying from their phone, and messages also go out from Messaging Me. Meta bills what
  goes out from Messaging Me, what they type in the app stays free, a few app features stop (broadcast lists, the away
  message), they must open the app at least every two weeks, and what they type there does not show in Messaging Me:
  the AI agent does not see their replies. Meta calls it coexistence: never write that word to the user, even when a
  tool result uses it, say "keep your WhatsApp Business app"; the mode `coexistence` only appears in your tool call.

Then ask ONE question at a time, in this order, each one until the tree ends: a question is never skipped on a guess.
Never pick a way on a guess, and never offer another one.

1. **The plan: Free or Pro?** `get_setup_state` gives it (`offre`). Free is driven entirely from here, with no
   console; Pro adds the console (the team Inbox, campaigns, dashboards) and includes a number we provide. Ask only if
   the user has not said and the workspace is on Free. If they want Pro, `subscribe_pro` returns its payment link
   (paying is their gesture); then go on.
2. **"Who pays Meta for your messages?"** Meta bills each template they send.
   - "I add a payment method (Visa / Mastercard) to my Meta Business account": Meta bills their templates to this
     payment method. Go to question 3. If they ask why a payment method, or what a Meta Business account is, give the
     page in their language: why, `aide.payer_meta`; the account, `aide.compte_meta_business`.
   - Credit line: they prepay their messages at Messaging Me, with no card at Meta (30 EUR excl. tax per number per
     month, paid when taken, even during the Pro plan trial). On Free, say it comes with the Pro plan, then go on with
     question 3. On Pro (from the first day of its trial) or on a confirmed Business, it is taken in the console: the
     Plan page, Credit line tab (https://console.messagingme.app/offre?tab=whatsapp, with `&lang=en` in English); if
     the tab says why it cannot be taken yet (a Business still in its trial, a Pro payment late), tell them that reason.
     On Enterprise, it comes with their contract: nothing to take. Paying is their gesture: never offer to buy the option
     from here. Once they say it is paid (the payment confirms within seconds, and the link reads the option itself), or
     on Enterprise, go on with question 3: `start_whatsapp_connection` in `apporte` or
     `fourni` then gives a link that connects without a card at Meta, and its `consigne` says the conditions.
   Every way that keeps the WhatsApp Business app (mode `coexistence`, or a resumed `fourni_application`) is paid with
   their card at Meta: say once, on such a way, that the credit line is not possible with the app.
3. **"Do you have a Meta Business account?"**
   - Yes: an API number. Ask whether they have an available number, one used in no WhatsApp app: yes, their own
     number (mode `apporte`); no number at all, a number we provide (mode `fourni`, 3.50 EUR excl. tax a month,
     included in Pro). Add one sentence: if their number is already used in WhatsApp or in the WhatsApp Business app,
     they keep it in the app (mode `coexistence`); in WhatsApp, the regular app, they first install WhatsApp Business on
     the same phone, which offers to take over that number with their chats. Never send a number used in WhatsApp to
     another number.
   - No: nothing to prepare, Meta's window has them create it along the way. Go to question 4.
   - "I don't know": tell them where to check (business.facebook.com; if they advertise on Facebook or Instagram, they
     probably have one), and that a missing account is created along the way. Go to question 4.
4. **"Do you already have the WhatsApp Business app?"** Only after No or "I don't know".
   - Yes: ask **"Do you want to use that number?"** (the one in their WhatsApp Business app). Yes: they keep the app
     (mode `coexistence`). No: a number we provide, connected through Meta's window (mode `fourni`, 3.50 EUR excl. tax
     a month, included in Pro); their app keeps its own number.
   - No: question 5. Without a Meta Business account and without the app, the number connects directly as an API
     number: never invite them to get the WhatsApp Business app for its own sake (only the WhatsApp case of question 5
     below), and never put a number we provide in it.
5. **"Do you already have a number you could use?"** Their business's number, connected to the official WhatsApp API.
   Ask it, even when the user is a business that surely has a phone line.
   - Yes: ask whether that number is used in WhatsApp, the regular app. Not used in any WhatsApp app: their own
     number as an API number (mode `apporte`), through Meta's window, which has them create the Meta Business account
     along the way. Used in WhatsApp, the regular app: they first install WhatsApp
     Business on the same phone, which offers to take it over with their chats, then they keep it (mode
     `coexistence`): never send it to another number.
   - No: a number we provide, connected through Meta's window (mode `fourni`, 3.50 EUR excl. tax a month, included in
     Pro), which has them create the Meta Business account along the way.

**The QR code link is no longer offered** (`filiere` `application`, an older way that only answered): never propose
it, and never pass `filiere` to `start_whatsapp_connection`. A workspace already linked that way (`numero.filiere`
`application`) only answers. To write first (templates, campaigns, Shopify messages), or on `numero_coupe` or
`numero_en_sommeil`, its way forward is to keep the WhatsApp Business app and connect the same number through Meta
(mode `coexistence`, accepted on such a workspace: Meta's window creates the Meta Business account, and the
conversations stay); if WhatsApp cut the number, another number through Meta.

**The connection**, steps 1 to 4. The `consigne` of `start_whatsapp_connection` for `fourni` and `apporte` starts with
what Meta requires (a Meta Business account, formerly Business Manager, which Meta calls a business portfolio in its
screens and its window can create, and for
their own number one used in no WhatsApp app): relay it once, before the link.

1. The mode the questions settled:
   - **a number we provide** (`fourni`): a dedicated number, paid on the page before it is assigned, included in Pro;
   - **their own number** (`apporte`): check that it is used in no WhatsApp app. One used in WhatsApp, the regular
     app, or in the WhatsApp Business app is kept with `coexistence` (in the regular app, they first install WhatsApp
     Business on the same phone, which takes it over with its chats): never send it to another number;
   - **their WhatsApp Business app, kept** (`coexistence`): in Meta's window they enter the number of their app and
     confirm in the app, on their phone;
   - **a number we provide, put in the WhatsApp Business app** (`fourni_application`): no longer offered, only resumed
     when `numero.reprise` gives it. Paid or obtained on the page, then the app's account created with it, then the
     same window as `coexistence`. The code is typed in the app, not in Meta's window.
2. `start_whatsapp_connection` with that mode returns a link valid for one hour and its `consigne`. First say what the
   `consigne` announces BEFORE the link (what will happen in Meta's window, who pays what on this way, the step by step
   guide): the user must know it before clicking. For `fourni`, that guide is `aide.numero_fourni` (the video of this
   way, 3 minutes), given before the link unless the credit line pays (its window is another one). Then write the full `url` on its own line, then the numbered steps of
   `consigne`, one per line, in the user's language: the page shows the same ones. For `fourni_application`, the steps are those of its `consigne` (the app's account, then "Keep my
   WhatsApp Business app"), with no Meta window before the account. For a number we provide through Meta's window
   (`fourni`): click the link; pay (or "Get my number" in Pro); click "Open the Meta window"; on the number screen, "Enter a new phone number", the country GB (+44), then the digits that follow +44;
   to get the code, "Phone call", NOT "Text message" (insist on it, and say it again on its own after the steps); the
   code shows on the page within seconds, and you write it here too; no code after 45 seconds: wait until Meta offers
   to send it again, and ask for it again, still by "Phone call"; go to Meta's last screen, "Finish"; only then come
   back here. Mention only in passing that if Meta's window offers nothing but "Text message", they take it (the text
   reaches us read aloud by a call, and the code usually shows the same way). Never write "I generated the link" without the link.
3. Call `watch_whatsapp_connection` in a loop, passing the `empreinte` it returned as `etat_connu`, and always pass
   the same `mode` to `watch_whatsapp_connection`: while nothing has moved, its answer carries a fresh link (`lien`)
   and tells you to write it if your last message did not contain the link. Loop until `connecte: true` (`coexistence: true` for the app
   kept), or until `a_activer: true` (then see `activer_numero`), and follow the `suite` of each answer. While a
   `suite` tells you to call `watch_whatsapp_connection` again, do not end your turn: once it ends, you cannot write
   anything until the user writes, and they are on the page or in Meta's window, not here. During this wait, never ask
   them to tell you when they have paid or are ready. Stop only after about forty calls in a row with no change (about a
   quarter of an hour), telling them to write to you when they resume. A `suite` that asks a question or offers a choice
   is answered by the user: ask it and end your turn. When a `code`
   shows up, write it in full: the user types it into Meta's window, or into the app for `fourni_application`. If the user comes back before the end ("I paid", "what now?"),
   tell them again where they are (the page, Meta's window, the number) before waiting again. Once connected, call
   `get_setup_state` before announcing anything: the credit offered for the first number arrives a few seconds after
   the connection; if it still reads 0, read it once more a few seconds later.
4. Right after the connection, follow the `suite` of `watch_whatsapp_connection` on who pays Meta: a card at Meta
   (Visa or Mastercard), without which templates do not go out, with its steps, which `get_setup_state` gives again
   (`etapes_carte_meta`) as long as Meta reports the card missing; or, when the credit line pays, no card at all, and
   a top-up of that credit line before the first templates; a number already connected with its card at Meta cannot
   move onto the credit line: the user writes to Support.

## activer_numero: a number Meta has not activated yet

The number is linked but Meta has not finished its verification: no tool does this step. Ask the user to open the
console's Home and click "Activer le numéro" (it sends a verification code by call or SMS), then call
`get_setup_state` again.

## creer_agent, completer_agent, activer_agent: the AI agent

0. If an agent was deactivated earlier (`agents.desactives`), ask whether to reactivate it or to build a new one:
   reactivating puts it back in the scenarios that use it.
1. Ask, in one short round: what the business does, its website address, the tone (formal or not), when a human
   must take over, whether someone can take over at set hours (which days and hours, and the time zone if not
   France), at any time, or never, and what the agent must never say.
2. `create_agent` with a label (the first agent of a workspace needs a little AI credit: `get_credit`, `buy_credit`).
3. If there is a website: `preview_site`, show the user which pages would be imported, then `import_site`. Without a
   website: `add_knowledge` with what the user tells you, or `import_document_text` for a document they give you. The
   agent cannot be activated without knowledge.
4. `update_agent`: the objective (the field that weighs most on its answers), the tone, the handover rules (when to
   pass to a human) and at least one stop rule (`sorties`). Send the full list of `sorties`: it is replaced as a whole.
   Then the team's hours, which decide what the agent promises when it hands over: at set hours,
   `set_business_hours` (the seven days, closed or one range each) then `set_transfer_mode` with `business_hours`
   (outside those hours the agent says when the team is back); at any time, `set_transfer_mode` with `always`; never,
   `set_transfer_mode` with `never`.
5. `set_agent_tools` with `chercher_connaissance` (the knowledge is only used if this tool is on) and `escalader`,
   unless the user said no human ever takes over: without it, the agent announces a human but nothing hands over.
6. `test_agent` on two or three realistic customer messages (each try is charged to the credit). Show the answers;
   adjust with `update_agent` if the user asks.
7. `activate_agent`. If it refuses, it lists what is missing: complete it, then try again.

## Actions: what the agent does in the user's application

When the user wants the agent to act in their application when a customer asks (cancel a contract, book a callback,
file a complaint), and only then: `set_agent_action` on the agent, with a name, an instruction (when to trigger it,
and what the agent then tells the customer) and the details to collect, each with a code, a label and a type
(`texte`, `nombre`, `date`, `email`, or `liste` with its values), all optional for the agent. The action is sent at
most once a day per contact through the outgoing webhook `agent.action`, unchecked by default. If an address already
serves the app (`list_webhook_endpoints`), add `agent.action` to it (`update_webhook_endpoint`, with its full list of
types, which replaces the current one) rather than creating a second one, which would have another
secret; otherwise `create_webhook_endpoint` with the type `agent.action`. Then write the handler in the user's app (the
payload is in the API documentation, the details in `fields` by code). Never change a field's code once the app reads
it. To edit an action, `set_agent_action` with its `action_id`: what you leave out stays, `champs` given replaces the
whole list. `get_agent` lists the actions, `get_conversation` shows those triggered in a conversation,
`delete_agent_action` removes one.

## choisir_repondeur: who answers customers

`set_default_responder` with `mode: "agent"` and the active agent's id. Only when `get_setup_state` asks for it: if a
responder is already chosen (Meta's agent, a scenario, the user's application), never change it unless the user asks.

## poser_bulle: the WhatsApp chat bubble

1. `create_widget` with a name and the sentence the visitor will send (it tells which site they come from).
2. Put the returned `balise` (a `<script ... async>` tag) in the project's HTML, just before `</body>`, on every page
   where the bubble should appear: the root layout or the base template. In Next.js, use `next/script` with the same
   `src` and `strategy="afterInteractive"` in the root layout. It never slows the page and never changes.

## pret: the test

Ask the user to write to the number from their phone, through the bubble or its `wa.me` link (`list_widgets`,
`waMeUrl`), and to confirm the agent answered: `list_conversations` and `get_messages` show the exchange, on every
plan. Then summarize what is in place, and what they can do next (templates, contacts, outgoing webhooks
for their app).

## When a tool refuses

- `plan_limit_reached` or `plan_feature_unavailable`: tell the user, with the upgrade link from `get_plan`. If they want
  the Pro plan, `subscribe_pro` returns its payment link. Never work around a plan limit.
- Outside the 24-hour window, only an approved template can be sent: see the `regles-whatsapp` skill.
- Any other refusal: read its message to the user, plainly, and suggest the gesture it names.

## Writing the application's code

When the user's app calls Messaging Me (sending templates, receiving webhooks), read the API documentation first:
https://console.messagingme.app/developers/api (for a language model: https://console.messagingme.app/llms.txt). The
app's API key goes in the `MESSAGINGME_API_KEY` environment variable. `create_api_key` creates it and shows it ONCE: write
it straight into the project's `.env` (a file git does not track), never repeat it in your answers or put it in code. Its scopes
are limited (no MCP, webhook or contact deletion scope: those keys are created in the console). The plan caps active
keys; revoking one in the console frees a place.

## Never

- Never put an API key in code or in a file tracked by git: the application's key goes in the `MESSAGINGME_API_KEY`
  environment variable.
- Never message a contact who said STOP. Sending a template to one number (`send_template_to_contact`), importing
  the Shopify customers (`import_shopify_customers`) and the Shopify store's messages (`set_shopify_message`) record
  consent on the user's behalf: for these three, ask no consent question. Campaigns still only reach contacts who
  agreed, and never launch a campaign without the user's explicit go.
- Never state what Meta charges from memory: prices change every quarter. Quote only the price a tool returns
  (`prix_meta` of `list_templates`, see the `regles-whatsapp` skill), or point to Meta's rate card.
- Never pay for the user: `buy_credit`, `subscribe_pro` and the number's page return a payment link; paying is their gesture.
